# VPS 端口分层与防火墙约定

> 更新日期：2026-07-29

本文记录本仓库 VPS 脚本采用的端口分层策略。IANA / RFC 6335 官方只把端口分为三大类：`0-1023` 系统端口、`1024-49151` 用户/注册端口、`49152-65535` 动态/私有/临时端口。下面的更细分段是本项目的工程约定，用来降低脚本之间互相撞端口的概率。

## 一、端口分层

| 范围 | 本项目用途 | 说明 |
|---:|---|---|
| `1-1023` | 保留端口，基本不用 | 知名服务端口集中区。例外：Hysteria2 / QUIC 可按需要使用 `443/udp`。 |
| `1024-16383` | 甬哥 `argosbx` 脚本协议端口 | 保留给原始 argosbx 体系，避免后续增强脚本抢占。 |
| `16384-24575` | 自生成代理协议端口 | `vless-raw-enc-argosbx-enhancer.sh` 管理的 Xray sidecar 协议入站使用，包括 VLESS RAW ENC、SS2022 等。 |
| `24576-49151` | nftables 转发入口端口 | `nftables-relay-manager.sh` 新增转发规则使用。 |
| `49152-65535` | SSH 随机端口 / 未来其它服务 | `setup-ssh-key-only-full.sh` 使用；这也是 IANA 动态/私有端口段。 |

`0` 是特殊保留端口，不作为正常监听端口使用。

## 二、脚本约定

| 脚本 | 端口范围 | 当前行为 |
|---|---:|---|
| `argosbx` 原脚本 | `1024-16383` | 本仓库不直接改它，只在其它脚本中避让它的端口记录。 |
| `vless-raw-enc-argosbx-enhancer.sh` | `16384-24575` | 安装/改协议端口时随机推荐；手动输入必须在范围内；避开本机监听端口、Argosbx 端口记录、旧 SS Rust 配置端口和同一 sidecar 内其它协议端口。 |
| `nftables-relay-manager.sh` | `24576-49151` | 新增规则随机推荐入口端口；文件导入的新规则也受范围限制；运行时导入/已有托管旧规则允许继续保留旧端口。 |
| `forwardx-nat-agent-adapter.sh` | 不固定 | NAT VPS 使用服务商后台映射后的内部端口；ForwardX 面板规则填内部端口，公网访问仍使用服务商分配的公网端口。 |
| `setup-ssh-key-only-full.sh` | `49152-65535` | 随机选择或手动指定 SSH 新端口；避开当前 SSH 端口、常见服务端口和本机 TCP 监听端口。 |
| `proxy-stack-orchestrator.sh` | 不固定 | 不推荐或内置机器端口；从实例 `services.tsv` 读取启用组件的协议、端口和来源。`managed` 排他拒绝其它 input base chain，`external` 不修改主机 input policy。 |

## 三、兼容策略

`nftables-relay-manager.sh` 可能已经托管过一些旧转发规则，入口端口不一定落在 `24576-49151`。这些旧规则不强制迁移，避免影响现有可用服务。

新的规则要按新范围走：新增规则、编辑规则时如果更换入口端口、从文件导入新规则，都应使用 `24576-49151`。编辑旧规则时，如果入口端口保持不变，可以继续保留旧端口。

## 四、检查命令

查看本机正在监听的端口：

```bash
ss -tulpen
```

查看 nftables 当前 DNAT / 防火墙规则：

```bash
nft list ruleset
```

查看 Linux 本机临时端口范围：

```bash
sysctl net.ipv4.ip_local_port_range
```

## 五、使用提醒

- 端口号只是工程约定，不是安全证明。真正是否暴露，取决于服务监听、系统防火墙、云厂商安全组和上游网络策略。
- `49152-65535` 官方属于动态/私有端口段。本项目把它用于 SSH 新端口，是为了和代理、转发脚本隔离；如果服务器有大量出站连接，应额外关注系统临时端口范围是否重叠。
- 新脚本推荐端口时会尽量随机，并检查已有监听或已知配置记录；云厂商安全组仍需要按实际端口单独放行。
- 同机全新部署、接管已有 Argosbx / Proxy Gateway Plus / sidecar，或按配置复刻时，可用
  [`scripts/vps/proxy-stack/README.md`](../proxy-stack/README.md) 维护每台机器的实例服务清单。
  仓库示例不代替实际 inventory，新增或修改服务时应更新实例清单后先预览，再显式应用。
