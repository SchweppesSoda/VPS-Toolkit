本轮仅本地工作流/文档修改与隔离测试，未 push、触发 GitHub Actions、发布、安装组件或

## 原因与范围

既有 `po0-check.yml` 只跟踪 PO0 relay/客户端等路径，`scripts/vps/3x-ui` 与
`scripts/vps/proxy-stack` 的测试不会因这些模块改动而自动运行。新增独立的 `vps-check.yml`
只跟踪这两模块、PO0 sidecar、`tools/vps`、工作流及 gitattributes；push main、PR 和手动
触发均可检查，不承担部署，也不改变 PO0 资产构建与发布范围。

Linux job 直接复用现有脚本：Python subscription exporter、Bash self-destruct exporter、
proxy-stack orchestrator；同时接入 T08 的合成 ZIP 校验回归。先检查 Python/Bash/ZIP 与
摘要工具存在，并运行受影响业务 shell 的语法检查。测试使用 synthetic SQLite、临时文件
及 mock 服务/nft/下载，不针对真实主机。

Windows job 复用原 `test-3x-ui-download.ps1`，通过本地编译的 mock `ssh.exe` 验证原生
参数/管道、哈希、截断、失败清理，以及真实 Bash/SQLite 导出到本地临时 ZIP。它在 Windows
PowerShell 5.1 启动，并检查可用的 PowerShell 7；不进行 SSH 连接。workflow 仅有
`contents: read` 权限。没有复制测试逻辑或引入新的测试框架。
